## 1. 背景与目标

- **现状**：老人靠记忆服药，子女无法确认是否已服（Q1）；无任何依从性数据（Q5 答"不知道"）。
- **目标**：把"吃药"变成"药盒响 → 老人取药 → 子女可见"的闭环；把处方录入从手工填表降到"拍一张 + 改几个字"。
- **硬件前提**：外购/代工药盒，型号与单台成本未定（Q3，见附录 B P1）。
- **非目标**：不做诊断、不做用药建议、不做药物相互作用判断、不做在线问诊、不做医保结算。
- **成功判据**：§3.3 两条线。

## 2. 用户故事与交互流程

- **US1（子女）** 我用 App 拍下处方，系统给出药名/剂量/频次草稿，我核对后保存，形成今天的服药计划。
- **US2（老人）** 到点药盒响铃并亮对应仓位灯，我取药，盒子记录本次已取。
- **US3（子女）** 我在 App 看到今日三次服药分别是"已服/漏服/未到时间"，漏服时收到推送。
- **US4（子女）** 我添加第二位家属共同查看（只读）。

流程：
1. 子女拍处方 → 模型抽取 `{药名, 规格, 单次剂量, 频次, 疗程}` → 用户逐项确认（**必须人工确认后才生效**）。
2. 生成每日计划 → 下发到药盒（蓝牙/WiFi，通道【待确认】）。
3. 到点：药盒响铃 30 秒 + 仓位灯闪；老人开仓取药 → 计为"已取"。
4. 5 分钟内未取 → 复响一次；15 分钟未取 → App 推送"疑似漏服"。
5. 每日 22:00 生成日结，写入依从性报表。

## 3. 效果定义

### 3.1 三层指标

| 层 | 指标 | 口径 | 现状值 | 目标值 | 因果假设 |
|---|---|---|---|---|---|
| 模型层 | 处方字段准确率 | 药名/剂量/频次三个字段全部正确且用户未修改的比例 | 【待确认：无基线，需先跑 300 张真实处方】 | ≥85%【假设 A1】 | 准确率决定"改几个字"还是"全重填"，是体验分水岭 |
| 模型层 | 抽取失败可解释率 | 失败时给出"重拍/手填"明确指引的比例 | 【待确认】 | 100%【假设 A2：失败必须可行动，不接受静默失败】 | 失败可行动 → 用户不放弃录入 |
| 使用层 | 按时服药率 | 计划时点 ±30 分钟内取药次数 / 应服次数 | 【待确认：Q5 无数据】 | ≥75%【假设 A3】 | 响铃 + 灯指示降低漏服 |
| 使用层 | 家属周活查看率 | 每周至少打开一次报表的家属账号占比 | 【待确认】 | ≥60%【假设 A4】 | 可见性带来督促 |
| 业务层 | 30 天留存（家属账号） | 首装后第 30 天仍活跃 | 【待确认】 | 【待确认：由业务定】 | 留存取决于是否真减少漏服焦虑 |

### 3.2 评测集

- **来源**：真实处方照片（含手写、复诊单、慢病长处方），由合作社区医院提供【待确认：谁能提供、是否需授权】。
- **规模**：300 张（其中手写 ≥60 张）【假设 A5】。
- **标注**：药师逐张标出四个字段真值【待确认：药师来源与工时】；两人标 + 分歧由第三人裁。
- **更新**：每次模型或 prompt 变更前补充 50 张新样本，旧样本保留以测回退。
- **防泄漏**：评测处方不进 prompt 示例；用户真实处方不进评测集（需授权）。

### 3.3 及格线

- **上线红线**：
  1. **剂量字段错误且用户未发现** → 0 例（一票否决：错剂量直接涉及人身安全）；
  2. 药名准确率 <0.80【假设 A6】不进灰度；
  3. 药盒漏响（应响未响）>1%【假设 A7】不许量产。
- **长期目标线**：字段准确率 ≥92%、按时服药率 ≥85%、家属周活 ≥70%。
- **依据**：剂量错误定 0 而非百分比——一条错剂量提示可能造成过量服药，风险量级与其他指标不同。

## 3a. Prompt Spec（行为合同）

- **角色**：处方信息录入助手。只把图片里的字读出来并结构化，不解释、不建议、不推断缺失项。
- **输入约束**：单张处方照片，≤10MB，分辨率 ≥800×1000；模糊/反光/裁切 → 直接返回失败码。
- **输出格式**：JSON
  `{"items":[{"name":str,"spec":str|null,"dose":str|null,"freq":str|null,"days":int|null}],"confidence":0-1,"failure":"blurry|handwriting|not_prescription|null"}`。
  字段读不出必须置 `null`，**禁止推测**（如把"1片"补成"1片/次，3次/日"）。
- **拒答与转人工**：
  - 非处方（快递单、说明书、药盒正面）→ `failure:"not_prescription"`，页面文案"这张不是处方，请拍处方的正面"。
  - 手写且置信度 <0.5 → `failure:"handwriting"`，文案"手写部分识别不清，请手动填写"。
- **正例**：清晰机打处方 → `items:[{"name":"苯磺酸氨氯地平片","spec":"5mg","dose":"1片","freq":"每日1次","days":30}], confidence:0.91`。
- **反例**：处方只写"氨氯地平 5mg 每日一次"却输出 `days:30` ——**错在凭空补疗程**，正确做法是 `days:null` 并让用户填。
- **变更所有权**：算法可改 prompt 与模型，产品经理批准；任何变更必须重跑 §3b 全量并附对比表。

## 3b. Eval Spec（可执行验收）

- **分层**：冒烟 30（机打清晰）/ 核心 200 / 对抗 40（手写、反光、折痕、遮挡）/ 长尾 30（多药同方、中药饮片、复诊单）【假设 A5】。
- **评分方式**：字段级规则比对（与药师标注）+ 人工确认"用户是否需要重填整张"。
- **rubric（单张处方，0–3）**：

| 分 | 判定 |
|---|---|
| 3 | 四字段全对，用户不用改 |
| 2 | 错 1 个非剂量字段，用户改 1 处即可 |
| 1 | 错 ≥2 个字段或剂量字段错但被判为低置信度并提示复核 |
| 0 | **剂量错且高置信度直接落库**、或凭空补字段、或把非处方当处方 |

- **上线线**：核心集 ≥2.4 均分；剂量字段准确率 ≥0.98；0 分样本 0 例。
- **一票否决**：任何 1 例 0 分（尤其是错剂量且高置信）。
- **映射**：字段准确率 ← 核心集规则判分；可解释率 ← 失败样本是否带 failure 码与指引文案。
- **回归触发**：换模型、改 prompt、改处方模板适配、改字段 schema → 全量重跑；每次发版必跑冒烟 30。

## 4. 能力边界与不承诺清单

**支持**：中文机打处方、常见口服固体制剂、单张 ≤6 种药【假设 A9】、iOS/Android App、药盒 4 仓位【同 A8】。
**不支持/不承诺**：
- 不判断药物相互作用、不判断重复用药（若要做，另立项目）。
- 不识别注射剂、外用药、中药汤剂剂量换算。
- 不给用药建议、不改医嘱、不替代医生药师。
- 不承诺"提醒即服药"——只记录取药动作，无法验证真正吞服（重要限制，需在 App 内说明）。
- 不做多患者（一台药盒绑一个用药人）。

## 4a. Agent 行为边界

`【不适用：本产品无模型驱动的自主工具调用——模型只做一次图片抽取并返回 JSON，下发计划、响铃、推送均由固定规则与定时器触发，不存在模型自主选择动作的链路】`

补充约束（非 Agent，但涉及对外动作）：App 推送只发本绑定家属；药盒只接收计划下发指令，不接受远程开仓。

## 5. 数据需求与回流

- **数据**：处方照片（敏感健康数据）、结构化用药计划、取药事件、推送日志。
- **存储**：照片本地优先还是上云【待确认：涉及健康数据合规，需法务与安全评】；上云则加密与保留期【待确认】。
- **回流**：用户对抽取结果的修改（改了哪个字段、改成什么）→ 进评测候选池；**照片是否可用于训练需单独授权**，默认不用于训练。
- **共享**：家属只读权限，可添加/移除；老人本人可见"谁在看我的记录"。
