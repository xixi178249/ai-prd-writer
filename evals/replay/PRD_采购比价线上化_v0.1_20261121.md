## 1. 背景与目标

- **现状**：比价走邮件 + Excel，6 名采购各自维护表格；审批靠转发邮件（Q1/Q2）。
- **痛点**：漏比（家数不足仍定标）、超阈值未走二级审批、过程不留痕；单笔耗时无数据（Q5 答"不知道"）。
- **目标**：把"发起比价 → 收报价 → 比价 → 定标 → 回写 ERP"收进一个系统，硬规则由系统拦，不留人工自由裁量空间。
- **非目标**：不做供应商准入、不做合同、不做价格趋势分析、不做自动选商评分模型（Q3 明确不用模型）。
- **成功判据**：§3.3 三条门槛全过。

## 2. 用户故事与交互流程

- **US1（采购）** 我新建比价单时，系统按物料行自动带出历史供应商，我补收报价，缺一家就提交不了。
- **US2（采购）** 报价收齐后我看到横向比价表，最低价高亮，同价按交期排序，我选一家定标。
- **US3（采购经理/财务）** 超过 5 万的定标进我的待办，我批或驳，理由必填。
- **US4（采购经理）** 我能导出近 3 个月所有比价单的家数与定标理由，应付审计。

流程：
1. 采购建单（物料行 + 数量 + 需求到货期）。
2. 逐家登记报价（供应商、单价、税率、交期、报价附件）。
3. 系统校验（规则见 §3a）→ 通过后生成比价表。
4. 选供应商 → 提交定标。
5. 金额 ≤5 万：采购经理单级审批；>5 万：采购经理 + 财务二级审批。
6. 审批通过 → 回写 ERP 建采购单（接口见 §5）。

## 3a. Prompt Spec

`【不适用：本产品无模型层，无 prompt】`
替代物：**校验规则规格**（评审与测试共用同一份，研发照此实现）：

| # | 触发条件 | 系统结果 | 用户看到 |
|---|---|---|---|
| R1 | 某物料行有效报价 <3 家 | 不允许提交比价单 | "该行仅 2 家报价，至少 3 家" |
| R2 | 报价缺税率或交期 | 该报价不计入有效家数 | "报价不完整，请补齐税率与交期" |
| R3 | 定标金额 >5 万且无二级审批 | 不允许定标生效 | "金额 5 万以上需财务二级审批" |
| R4 | 定标非最低价且理由为空 | 不允许提交 | "请填写选择理由（非最低价必填）" |
| R5 | 同一供应商对同一行重复报价 | 保留最新一条，旧条目标记作废 | "已作废旧报价，保留最新的" |
| R6 | 报价单价与附件金额不一致 | 允许保存，提交时提示二次确认 | "报价单与附件金额不一致，确认继续？" |
| R7 | 物料行无报价就点定标 | 不允许 | "该行无报价，无法定标" |
| R8 | 回写 ERP 字段缺失（成本中心/科目） | 阻止回写，不阻止审批 | "缺少成本中心，无法建单，请补" |
| R9 | 审批人驳回 | 定标退回，状态回"比价中"，理由必填 | 通知发起人 |
| R10 | 同一物料 30 天【假设 A7】内已定标 | 允许新建，但提交时提示"近期已定标" | 提示 + 需勾选"确认重新比价" |

变更所有权：规则由采购经理书面提出、产品经理评审、研发实现；任一规则变更必须同步更新本表与 §3b 用例（一条规则至少对应一条用例）。

`【不适用：本产品无模型输出，无 rubric 判分】`
替代物：**验收用例**（测试照此建用例，业务照此签收）：

| 编号 | 输入 | 预期 | 判定 |
|---|---|---|---|
| C1 | 某物料行 2 家报价，点提交 | 拒绝，提示"至少 3 家" | 提示文案含"3 家"且未生成比价单 |
| C2 | 加第 3 家报价后提交 | 通过，生成比价表 | 比价表 3 行，最低价高亮 |
| C3 | 报价缺税率 | 该报价不计入家数 | 有效家数仍 2，提交被拒 |
| C4 | 金额 6 万，仅采购经理审批 | 不生效，仍待财务 | 状态"待财务审批" |
| C5 | 金额 6 万，两级都批 | 生效并可回写 | 状态"已定标"，ERP 建单成功 |
| C6 | 定标非最低价、理由为空 | 拒绝提交 | 提示"请填写选择理由" |
| C7 | 同供应商同物料再报一次 | 旧报价作废 | 有效报价 1 条，最新那条在 |
| C8 | 报价与附件金额不一致 | 保存成功，提交时二次确认 | 弹出确认框，取消则不定标 |
| C9 | 回写 ERP 缺成本中心 | 阻止回写、审批保留 | ERP 无单据，页面提示缺字段 |
| C10 | 审批驳回 | 退回"比价中"，通知发起人 | 状态正确，理由可见 |

- **评分方式**：全规则判定，无人工打分。
- **通过门槛**：10 条全过 + 试点 20 笔真实单回写成功 ≥19 笔，才放行全量。
- **一票否决**：C4（越权审批）或 C9（脏数据进 ERP）任一失败 → 不许上线。
- **回归触发**：规则表任何一条改动、ERP 接口字段改动、权限模型改动 → 全量重跑 10 条。

## 4. 能力边界与不承诺清单

**支持**：单币种（人民币）、单公司主体、直采比价、≤50 行物料【假设 A5】、≤10 家供应商/行【同 A5】。
**不支持/不承诺**：
- 不做供应商自动推荐或评分（Q3）。
- 不做框架协议价、阶梯价、汇率换算。
- 不做多主体、多币种、跨境。
- 不承诺替代 ERP 的采购单管理，本系统只管"比价与定标"，单据生命在 ERP。
- 不做报价附件的自动识别（附件只存不解析）。

## 4a. Agent 行为边界

`【不适用：无模型驱动的工具调用与自主决策，系统对 ERP 的写入均由固定规则与人工点击触发，不存在 Agent 自主步进】`
但接口层面仍受约束：回写 ERP 仅允许 `create_purchase_order` 一个动作，不允许改价、不允许改已建单；失败重试 ≤2 次后转人工。

## 5. 数据需求与回流

- **数据来源**：物料主数据、供应商主数据、历史成交价、组织与成本中心，均需来自 ERP（字段清单【待确认：由研发与 ERP 管理员出】）。
- **回写**：定标通过后建采购单；接口方式（API/中间表）、幂等键、失败重试策略【待确认：接口未定，Q6】。
- **留痕**：所有状态变更写审计日志（谁、何时、从什么状态到什么状态、理由）；保留时长【待确认：财务合规要求】。
- **回流**：定标价进历史价库，供下次比价参考；无模型训练需求。

## 6. 成本预算

- **开发**：前端 4 页 + 规则引擎 + ERP 接口，人日【待确认：由研发评】。
- **运行成本**：无模型调用费；仅为服务器与存储，量级【待确认：由运维给】。
- **替代成本说明**：本方案省的是采购与财务的邮件往返时间，量化收益需 §3.1 使用层基线，现无基线。

## 7. 兜底与风险

| 风险 | 表现 | 兜底 |
|---|---|---|
| ERP 接口不稳 | 定标成功但建单失败 | 定标与建单分离：建单进重试队列，失败告警给采购，允许手工补建 |
| 规则误拦 | 合法业务被卡（如独家供应） | 提供"例外申请"：采购经理审批后可跳过 R1，理由必填并进审计 |
| 数据迁移错 | 历史比价单导入缺字段 | 历史单只读、不参与新流程，不做强迁移 |
| 审批人不在 | 流程卡死 | 超 2 个工作日【假设 A6】未处理 → 提醒并允许指定代理人 |
