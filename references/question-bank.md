# 追问题库与话术

## 一、通用必问（8 条：任何场景都问，缺一条都要补）

| # | 问题 | 落到哪一节 |
|---|---|---|
| 1 | 谁在什么场景下遇到什么麻烦，现在怎么对付 | §1 |
| 2 | 不用 AI 的话，规则／人工／买现成产品各卡在哪 | §1 |
| 3 | 谁是主要使用者，能力水位与信任阈值如何 | §2 §4 |
| 4 | AI 答对时，用户接下来做什么 | §2 §3.1 产品层 |
| 5 | AI 不确定／答错时，用户会怎么反应 | §2 §7 |
| 6 | 冷启动数据从哪来，能不能拿到，合不合规 | §5 |
| 7 | 上线三个月后，看哪 1–2 个数字说这东西成了 | §3.1 §3.3 |
| 8 | 硬约束：预算量级、合规要求、必须复用的系统、绝对不能做的事 | §4 §6 |

## 二、按场景类型补充

- **软件 / AI 应用**：权限与数据边界、核心动作闭环、失败定义、并发与响应要求。
- **数据与算法**：数据来源与标注、评测集构成、离线指标 vs 线上效果、基线与上线门槛。
- **内容与服务**：受众与渠道、生产链路产能、审核与合规、效果归因方式。
- **硬件与线下**：物理与场地约束、角色与班次、异常与兜底、成本结构、验收方式。

## 三、提问格式（强制）

每个问题必须包含四件东西：

1. 一句话问题（具体，禁止"为了更好地帮您……"）；
2. 3–4 个可点选项，第一个标 `(Recommended)`；
3. 每个选项后一句"选它会导致什么差异"（用户靠这个判断，不是靠感觉）；
4. 末位固定一项「你帮我定」——允许用户把决定权交回来。

## 四、笼统判定与复问

**笼统词表**：好用、智能、高效、提升体验、赋能、闭环、行业领先、大幅、显著、全面、一站式、精准、便捷。

判定规则：命中笼统词 **且** 缺少可验证对象（谁 / 多少 / 怎么量 / 什么算错）→ 复问一次：

> 具体到可验收的说法是——谁在用、现在是多少、目标是多少、怎么算？

**复问的三种打法（按场景挑一种）**

- 换成三档让用户选：
  > A 错了用户自己能发现并纠正（容错高）／B 错了会误导决策（需人工复核）／C 错了会造成对外事故（必须拦死）
- 换成对比锚点：
  > 现在这件事人工做一次大概多久？AI 做到多久你会觉得"值了"？
- 换成反面问题：
  > 哪种情况你会立刻把它关掉不用？

复问上限 1 次。仍笼统 → 记 `【待确认：<字段>口径，需<角色>确认】`，继续下一个。

## 五、"不知道"的处理

不追第二次。写成：

```
【待确认：<字段名>；影响 §<章节>；建议由 <角色> 提供】
```

并在 P2 摘要的"待确认"段汇总，说明"这条不定，下游哪一章会被卡住"。

## 六、题量节奏

- 8–15 题为宜；满 15 题强制进入 P2 摘要，缺项全部进【待确认】。
- 每 5 题打一次小结：回显"已确认 5 条 + 还剩 3 项必问"，让用户知道进度并允许纠错。
- 用户说"可以了 / 直接写 / 别问了 / 继续" → 立即进 P2，不再追问。

## 七、P2 摘要的三段结构

```
已确认（可直接写进正文）
代定（我替你定的，附理由，可推翻）
待确认（缺什么、卡住哪一章、建议谁补）
```

用户回「确认」才动笔；回具体修改意见则改完再确认。
