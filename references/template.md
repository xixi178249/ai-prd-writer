# 固定模板（章节锁定：只填内容，不增删章）

> 用法：照抄章节号与标题。每节下的「必填」是交付要求、「常见坑」是自查项，两者都不出现在最终稿里。

---

## 1. 背景与目标

- **必填**：要解决的业务问题（谁、什么场景、现在怎么扛）；为什么用 AI 而不是规则/人工——含反证：什么问题规则能解、什么问题人工更划算。
- **必填**：现状的可量化描述至少一条（无数据则 `【待确认：现状值由谁提供】`）。
- **常见坑**：把"提效"当目标；不写现有替代方案；一上来就讲方案。

## 2. 用户故事与交互流程

- **必填**：正常路径（AI 回答符合预期时，用户逐步做什么）。
- **必填**：异常路径（AI 不确定／答错／超能力边界时：重问、降级、转人工、给替代方案）。
- **常见坑**：只有 happy path；异常路径写成"提示用户重试"；不定义"不确定"的判定信号。

## 3. 效果定义（AI PRD 的核心新增）

### 3.1 目标指标

- **必填**：三层指标各给「口径 + 现状值 + 目标值」
  - 模型层：准确率／召回／幻觉率／拒答率…（写明测试集与算法）
  - 产品层：采纳率／修改率／完成率／平均交互轮次…
  - 业务层：省时／转化／人力成本／投诉率…
- **必填**：三者之间的**因果假设**——为什么模型层提升会带来产品层变化、产品层变化为什么传导到业务层；哪一环最不确定。
- **常见坑**：只写模型指标；指标无口径（谁算、分母是什么）；三层指标互不相干。

### 3.2 评测集

- **必填**：来源（真实抽样／人工构造／开源／历史 bad case）、规模、标注标准（谁标、几个人标、分歧怎么处理）、更新机制（多久轮换、如何防泄漏进训练）。
- **常见坑**：写"1000 条测试集"却不写从哪来；不写谁标、怎么保证一致性。

### 3.3 及格线

- **必填**：上线红线 vs 长期目标线，**给具体数字**；每根线给出定这个数的依据（成本／风险／用户容忍度／合规要求）。
- **常见坑**：只给一句"准确率 90%"；红线和目标线同一个数。
- **非 AI 场景**：三层仍要有，但换名——过程层（提交及时率、完整率）／使用层（单次耗时、填写率）／业务层（闭环时延、复发率）。红线与目标线照旧给两个数。

## 3a. Prompt Spec（行为合同）

- **必填**：角色 / 语气 / 输入约束（能接受什么、遇到什么就拒）/ 输出格式（结构、长度、必须包含的字段）。
- **必填**：拒答与转人工话术、失败兜底话术（用户看到的具体句子）。
- **必填**：正例 1–2 条、反例 1–2 条（反例要写清"哪里错、正确应该怎样"）。
- **必填**：变更所有权（谁可改、谁批）与回归门禁（改了什么必须重跑 §3b）。
- 示例 Prompt 放附录，并标注"非最终实现"。
- **非 AI 场景**：本节换标题为「校验规则规格」，写成表：条件 → 结果（什么输入不允许提交、什么要二次确认、什么要留痕）。这不是删除章节，是换内容。

## 3b. Eval Spec（可执行验收）

- **必填**：用例分层（冒烟 / 核心 / 对抗 / 长尾）与每层数量、评分方式（规则判定 / 模型判分 / 人工）。
- **必填**：rubric——每条分档写清"什么样得几分"，禁止"好/中/差"这种无锚点档位。
- **必填**：上线线 / 目标线 / **一票否决项**（命中即不许上）。
- **必填**：与 §3.1 产品层指标的映射；何种变更触发全量回归。
- **Agent 类补充**：是否评轨迹（工具选择是否合理、步数、是否越权）；越权是否一票否决。
- **非 AI 场景**：本节换标题为「验收用例」，写成表：编号 / 输入 / 预期 / 判定。必须给通过门槛（如"6 条全过才进试点"），否则验收会变成感觉验收。

## 4. 能力边界与不承诺清单

- **必填**：明确支持的场景（具体到任务类型，不写"各类问答"）。
- **必填**：明确不支持的场景。
- **必填**：已知失败模式——写具体表现（如"多轮指代消解失败，第二轮开始答非所问"），不写"可能不稳定"。
- **必填**：不承诺的效果（如"不承诺替代专业审阅"）。
- **必填**：高风险场景的强制阻断规则（命中即拒答／转人工），并说明判定条件。

## 4a. Agent 行为边界（有工具／副作用时必填）

- **必填**：完成证据——怎么判定任务真的完成了（而非模型自称完成）。
- **必填**：工具白名单与权限（只读／可写／可对外发送分别列出）。
- **必填**：风险分级与确认节点（哪类动作必须人工点头）。
- **必填**：失败出口（重试几次、退到哪一步、怎么回滚）。
- **必填**：任务预算上限（步数／时长／花费）。
- 无工具、无副作用时写 `【不适用：无外部调用与副作用】` + 一句原因。

## 5. 数据需求与回流设计

- **必填**：冷启动数据来源（多少、谁给、能不能商用、缺什么）。
- **必填**：线上回流机制（埋点字段、bad case 收集路径、标注分发、回流周期）。
- **必填**：数据合规红线（什么不能采、什么不能存、留存多久、脱敏方式）。

## 6. 成本预算

- **必填**：单次调用成本估算——token × 单价 ÷ 典型长度，写明假设（模型档位、平均输入输出长度、缓存命中率）。
- **必填**：规模化后的月度成本（按日活 × 频次推算，假设要写出来）。
- **必填**：告警阈值与降级策略（超预算先降什么：模型档位／上下文长度／并发／关闭非核心功能）。

## 7. 兜底与风险

- **必填**：置信度分级与降级链路（高／中／低各走哪条路，用户看到什么）。
- **必填**：人工介入触发条件（什么信号触发、谁来接、响应时限）。

## 8. 上线计划与灰度策略

- **必填**：灰度范围（人群／流量／场景）、观察周期、回滚条件（哪个指标跌到多少就回）。
- **必填**：Prompt / 模型版本 / 工具权限三类变更各自的灰度与回滚方式。
- **禁止**：编造日期。日期一律 `【待确认：需负责人给档期】`；可用 T+0/T+2 相对骨架并标注"建议"。

## 9. 后续迭代计划

- **必填**：数据飞轮——下一轮优化用哪批数据、怎么验证有效（对比口径）。
- **必填**：Eval 集扩充计划与"评测饱和"处理（分数到顶后：换更难样本 / 换指标 / 换任务）。
